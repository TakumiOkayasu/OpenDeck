# 拡張利用の要件案

基盤を変更せずに外部の拡張を追加し、利用するための要求を整理する。
[全体要件](../requirements.md)を前提とする。入力能力の要件は、その能力を利用する場合に適用する。
今回確認した利用要求と、次段階の検討案を扱う。現行実装の対応済み機能を表すものではない。

基盤は抽象化した入力データと操作の接続点を提供し、個別操作の処理は拡張側が実装する。
拡張作者が機器との接続やキー入力監視を実装する必要はない。
以下の導入・稼働管理は基盤を利用するホストの要求・提案として扱い、基盤の能力提供とは分ける。

## 必要な振る舞い

- 利用者が選んだ拡張を導入し、その提供する操作を既存の入力へ割り当てられる。
- 自作した拡張と、配布元から入手した拡張を、対応条件を満たす範囲で利用できる。
- 入手元と実行に必要な条件を分け、入手元だけを理由に実行可能と判断しない。
- 拡張を追加・変更しても、機器との接続や基盤の共通処理を作り直す必要がない。
- 拡張が必要な入力、対象、設定、表示先を接続でき、拡張の処理内容が基盤の共通仕様にならない。
- 同じ拡張の操作を別の場所へ割り当てた場合も、それぞれの設定と状態を取り違えない。
- 拡張の開始・終了と利用不能を把握でき、終了した拡張へ入力や通知を送り続けない。
- 拡張やその実行環境が利用できない場合、対応していない理由を成功と区別できる。
- 接続元が利用不能になったことを、正常な入力の終了と取り違えずに拡張へ伝えられる。
- 利用環境を変更した場合も、対応する拡張について共通の割り当てと操作の意味を維持できる。

短押し・長押しなど操作固有の解釈は、その解釈を必要とする拡張が決める。
基盤は個別操作の仕様や開発予定を持たない。

## パッケージと機能の割り当て

一つの拡張パッケージが複数の機能を提供し、利用者はその中から操作を選んで各ボタンへ割り当てられる。
パッケージの導入単位と、入力へ割り当てる操作の単位を分ける。
同じパッケージの異なる操作を別々に割り当て、同じ操作も設定を分けて利用できる。

回転と押下ができるノブの利用は[回転入力の要件](rotation.md)に従う。
単発押下、通常の回転、押しながら回転する操作へ、別々の振る舞いを割り当てられる。
一つのノブに属する操作を一つの拡張実装へ集めることは要求しない。
選択した操作の接続に必要な能力は操作単位で判断し、パッケージ全体から推定しない。
必要な入力能力を提供できない場合は、利用可能とせず不足を示す。

対象のON/OFFの反転、明示指定、状態照会、再起動や外部変更時の同期は、その操作を実装する側で定める。
基盤はこれらを押下・回転への割り当ての共通必須条件にしない。
入力の押下状態、二状態の表示、対象のON/OFF状態は別の情報として扱う。

## 成立条件

外部に用意した拡張を基盤の改変なしに導入し、その操作を選択・割り当て・実行できる。
必要な設定と状態が対応する操作へ届けられ、別の割り当てと混ざらない。
一つのパッケージが提供する複数の操作を別々のボタンへ割り当て、選んだ操作だけを実行できる。
押下と回転へ異なる操作を割り当てられ、必要な入力能力の不足を対応済みと取り違えない。
終了・開始失敗の後に、不要な実行や通知の対応が残らない。
同じ入力を利用する複数の拡張が、互いの入力を奪い合わずに受け取れる。

既存拡張については、対象とした拡張が必要とする能力を提供して動作を確認した範囲を、互換性の確認範囲とする。
導入できたこと、開始できたこと、割り当てた操作が使えることを、それぞれ区別する。

## ホストで初回に検証する利用場面 (提案)

信頼する外部拡張の単発操作を選び、個別に設定して入力へ割り当て、実行から終了までを確認する。
利用者が拡張を増やすたびに基盤を編集せず、異なる設定を混同せず利用できることを先に検証する。
失敗時も、利用できた状態や終了した状態と取り違えないことを確認する。

これは検証順序の候補であり、継続入力の共有、必要な表示や既存資産の利用要求を削除しない。
基盤の押下・回転能力の設計や提供は、このホストの実装完了を前提にしない。
実行できる拡張の条件と運用上の制約を確認してから、初回の範囲を確定する。
責務と契約は[基本設計案](../design/extensions.md)、具体方式と検証順は
[設計・実装プラン](../plans/extension-host.md)を参照する。

## 未確定の範囲

| 項目 | 確認する内容 |
| --- | --- |
| 最初の到達点 | 自作拡張の導入と既存拡張の互換利用を、どの順序と範囲で確認するか |
| 互換対象 | 調査した候補のうち初回に対応を検証する範囲と、その拡張が必要とする能力 |
| 導入と更新 | 導入元、更新、削除と、既存の割り当てを維持する範囲 |
| 設定の保持 | 拡張全体と割り当てごとの設定、再開時に復元する範囲 |
| 必要な能力 | 初回に提供する入力・設定・表示などの範囲と、利用条件 |
| 回転入力の接続 | [回転入力の要件](rotation.md)を満たす能力と操作を接続する方法。入力契約の設計はホストの検討と分ける |
| 配送先の失敗・停滞 | 他の拡張への配送と、まだ渡していない入力をどう扱うか |
| 失敗からの再開 | 利用不能や開始失敗後に、利用者がどのように再開するか |

責務と境界の検討は[拡張ホストの基本設計案](../design/extensions.md)で扱う。
