# 既定出力の変更通知を実機で確認する

`tools/output_volume_diagnostic.py` は、Windows/macOS の既定出力を購読し、
音量とミュートの初期値と通知後の読取結果を JSONL へ記録する。
診断は設定を書き換えず、N4 Pro や Device SDK を使わない。

## 採取

[README のセットアップ](../README.md#セットアップ)を済ませ、リポジトリのルートで実行する。

```sh
mise exec -- uv run python tools/output_volume_diagnostic.py --seconds 30
```

`--seconds 0` で購読・初期読取・解除だけを確認できる。
標準出力を保存する場合は、実行ごとに異なるファイル名を指定する。

採取開始前に、OS の設定画面で既定の出力機器名を控える。
30 秒以内に、確認したい操作を OS の設定や機器側で行い、実施時刻と結果を控える。
操作ごとに採取を分けると、通知後の値と照合できる。

- 既定機器の音量またはミュートを変更する。
- 既定出力を別の機器へ切り替える。
- 取り外せる既定機器を切断し、再接続後の出力を確認する。

## ログの読み方

- `session` は採取時間と OS 情報を示す。
- `snapshot` の `trigger` が `initial` の場合は購読開始後、`change` の場合は変更通知後に読み取った値。
  `volume` と `mute` は別々に読み取り、取得できない項目には `reason` と `message` が入る。
- `time` は各行を出力した UTC 時刻。OS の通知発生時刻は記録していない。
  複数の通知がまとまることがあり、行数は OS 上の変更回数と一致するとは限らない。
- `finished` は購読とアダプターを解放して正常に終了したことを示す。
  中断は `stopped`、購読や解放の `VolumeError` は `error` として記録する。

機器名と操作時刻は手動の記録と照合する。
試験結果には OS、機器名と接続方式、操作時刻、通知の有無、取得できた値や失敗理由を記載する。
出力の対応条件は [Windows](windows-volume.md) と [macOS](macos-volume.md) を参照する。
