# 全体要件

Mirabox N4 Proの操作ソフトを置き換え、利用者が必要な操作を追加・割り当てでき、既存のソフトや資産も活用できるようにする。

この文書は、操作ソフト全体に共通する要求を管理する。入力手段、操作内容、操作対象、必要な表示のいずれも、特定の機能や対象種別に固定しない。個別の操作が必要とする振る舞いと対象範囲は、対象ごとの要件文書で管理する。

具体仕様は基本設計以降で定める。このリポジトリの文書を正本とし、共通要件は参照して利用する。

## 目的と利用者

利用者は左手デバイスを日常の操作装置として使い、必要な操作を自作・追加したい。利用する入力手段や対象が変わっても、実行したい操作を継続して使えることを求める。

## 共通の要求

| 要求 | 利用者に必要なこと |
| --- | --- |
| 操作の追加 | 必要な操作を追加し、利用できる |
| 対応付け | 入力手段、操作内容、操作対象、必要な表示を対応付けられる |
| 組み合わせの変更 | 対応する入力手段や対象、表示先を変更しても、同じ目的の操作を使える |
| 結果と状態の把握 | 必要な実行結果や対象の状態を、対応が分かる形で把握できる |
| 既存資産の利用 | 合意した既存資産を、対応する範囲で再利用できる |

入力手段の種類によって実行する操作の意味を固定しない。利用者が設定した対応に従って動作することを求める。結果や状態の扱いは、個別の操作に必要な範囲で定める。

## 共通の利用の流れ

利用者は、実行したい操作とその対象を選び、入力手段と必要な表示を対応付ける。設定した入力から操作を実行し、必要な結果や状態を確認する。

## 利用環境と品質要求

当面はWindowsで日常的に利用できることを求める。将来macOSへ対応する際にも、共通する操作の意味と利用者の目的を維持する。

日常の連続した操作に支障を与えない応答性と安定性を求める。利用者の設定した対応と実行結果が一致し、失敗や利用不能を成功した状態と取り違えないことを求める。

入力手段、操作対象、表示先、利用環境の変更に対応でき、必要な操作を追加しやすいことを求める。

## 共通の成立条件

| 確認する要求 | 利用者から観察できる成立条件 |
| --- | --- |
| 操作の追加と対応付け | 追加した操作を割り当て、設定した対象へ実行できる |
| 組み合わせの変更 | 対応する組み合わせへ変更しても、意図した操作を利用できる |
| 結果と状態の把握 | 必要な情報が、実行した操作や選んだ対象に対応している |
| 既存資産の利用 | 合意した資産を、必要な利用範囲で使える |
| 利用環境への対応 | 対応する環境で、共通する目的の操作を継続して利用できる |

## 全体で未確定の要求範囲

| 項目 | 確認する範囲 |
| --- | --- |
| 初期完成範囲 | 最初に使えるようにする範囲と優先順 |
| 置換の範囲 | 純正操作ソフトへの実行時の依存をどこまでなくすか |
| 既存資産 | 利用したい資産と、必要な利用範囲 |
| 保存と復元 | 設定や割り当てを保持し、再利用する範囲 |

個別の操作に関する未確定事項と成立条件は、その操作の要件文書で扱う。
