# N4 Pro 表示・入力の実機診断

PR #24 の公開 API を使う手動診断。表示と入力の対応は実測する。実行中は画像が置き換わり、終了後の表示復元は保証しない。起動ロゴやファームウェアは変更しない。操作にアプリを割り当てない。

## 準備と起動

- Windows ネイティブ環境、N4 Pro 1 台。純正ソフトなど機器を使用するアプリを終了する。
- [README のセットアップ](../README.md#セットアップ)に従い、固定 SDK の submodule とデバイス用依存を準備する。`make_buttons` や通常の OpenDeck アプリは同時に動かさない。
- 対象 checkout のルートで PowerShell を開く。複数台なら原則 1 台にする。複数台で実行する場合のみ、列挙順を確認し `--device-index 0` のように指定する。番号は固定の機器 ID ではない。

```powershell
git rev-parse HEAD
git submodule status
Start-Transcript -Path .\n4pro-diagnostic-log.txt
mise exec -- uv run python tools/n4pro_display_diagnostic.py
Stop-Transcript
```

`Start-Transcript` のログには端末に表示された情報が記録される。実測内容も下の表へ記入する。`Ctrl+C` で中断し、処理が終了してから `Stop-Transcript` を実行する。エラーや切断があればその時点で中断し、全文と直前の操作を記録する。

## 確認手順

1. 最初の Enter で背景 `BG` を送る。結果を目視・撮影してから次へ進む。送信完了は描画完了を意味しない。変化がなければ 10 秒程度観察し、未表示または遅延として記録する。指定時間は診断上の観察目安であり SDK の保証ではない。
2. 次の Enter で通常ボタン向け D1〜D10、副画面向け D11〜D14 を送る。各ラベルの実際の位置、見切れ、向き、色を記録し撮影する。図柄左上は赤、右上は緑、外周は白枠、背景は格子。画像はスクリプト内で生成する PNG で、通常 112 x 112、副画面 176 x 112、背景 800 x 480。SDK が変換するため、このサイズがタッチ座標範囲を表すわけではない。
3. 続けて Enter を押すと入力を記録する。画面の左上・右上・中央・左下・右下を順番に一度ずつタッチし、その後左右それぞれにスワイプする。各操作の間を空け、時計とログを照合する。タッチは複数座標が出る場合があるので、開始・終了や軌跡を勝手に補わない。次に通常ボタンを一つずつ押し、物理位置と `input-N` を記録する。
4. Ctrl+C で終了しログを保存する。観測した表示を写真、座標と入力をログで照合する。ログ中の `display-N` と `input-N` は別の名前空間であり、同じ番号が同じ物理位置を示すとは仮定しない。

画像描画先の指定は公開 API の引数で、SDK の画像スロット番号ではない。実装上の変換は表示先 1〜5 → SDK 11〜15、6〜10 → SDK 6〜10、11〜14 → SDK 1〜4。表示先 11〜14 が実際にどの副画面領域へ現れるかは観測する。

## 既存テストと実機確認の境界

PR #24 は fake transport と固定 SDK で描画先変換、画像変換、イベントの受け渡しを検証済み。fake の成功は実機の画像位置、表示形式、座標と画面位置の対応、左右スワイプ、描画完了を保証しない。今回の fixture が出力した送信ログも実機の成功を証明しない。実機で観測・記録するまで各項目は未確認とする。
