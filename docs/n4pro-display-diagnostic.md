# N4 Pro 表示・入力の実機診断

PR #24 の公開 API を使う手動診断。表示と入力の対応は実測する。実行中は画像が置き換わり、終了後の表示復元は保証しない。起動ロゴやファームウェアは変更しない。操作にアプリを割り当てない。

## 準備と起動

- Windows ネイティブ環境、N4 Pro 1 台。純正ソフトなど機器を使用するアプリを終了する。
- [README のセットアップ](../README.md#セットアップ)に従い、固定 SDK の submodule とデバイス用依存を準備する。`make_buttons` や通常の OpenDeck アプリは同時に動かさない。
- 対象 checkout のルートで PowerShell を開く。複数台なら原則 1 台にする。複数台で実行する場合のみ、列挙順を確認し `--device-index 0` のように指定する。番号は固定の機器 ID ではない。

```powershell
mise exec -- uv run python tools/n4pro_display_diagnostic.py
```

実行するたびに `logs/diagnostics/n4pro-diagnostic-日時.jsonl` が作られる。保存先のディレクトリがなければ作成し、既存ファイルは上書きしない。保存先を指定する場合は `--output .\result.jsonl` を付ける。`Ctrl+C` で中断でき、それまでの記録は残る。エラーが出た場合も JSONL と画面のエラーを保存する。

## 確認手順

1. 最初の Enter で背景 `BG` を送る。目視・撮影してから次へ進む。送信の正常終了は描画完了を意味しない。変化がなければ 10 秒程度観察する。これは観察の目安であり SDK の保証ではない。
2. 次の Enter で通常ボタン向け D1〜D10、副画面向け D11〜D14 を送る。各ラベルの位置、見切れ、向き、色が分かるように撮影する。左上は赤、右上は緑、外周は白枠、背景は格子。画像は PNG で通常 112 x 112、副画面 176 x 112、背景 800 x 480。サイズはタッチ座標範囲を表さない。
3. 画面の指示ごとに Enter を押し、`GO` が表示されてから 5 秒以内に示された操作を行う。タッチ 5 位置、左右スワイプ、通常ボタン 10 個の順。ボタンは左上から右へ、次の段も左から順に押す。1 回の操作で複数座標が届く場合もそのまま保存する。
4. 全操作が終わると終了する。途中でも Ctrl+C で終了できる。JSONL と写真を一緒に保管する。画像の位置や向きは写真から確認する。プログラムは画面の実際の見た目を取得できない。

JSONL は 1 行が 1 レコードで、時刻付き。`session` に OS、Python、Git リビジョン、SDK リビジョン、device index を保存する。取得できないリビジョンは `null`。`image_sent` は API 呼出しの復帰、`step_start` / `step_end` は操作の区切り、`button` / `touch` / `swipe` は実際に取得した入力、`error` / `stopped` / `finished` は終了状況を示す。`finished` は手順完了であり、実機の表示・入力の成功を意味しない。操作時間外に保留されていた入力の `step` は `null` とし、次の操作に割り当てない。記録時刻は取得時刻であり、遅延して届いたイベントの発生時刻ではない。未操作、無反応、中断を成功と判定しない。JSONL にはエラー内容も含まれるため、共有前に内容を確認する。

画像描画先の指定は公開 API の引数で、SDK の画像スロット番号ではない。実装上の変換は表示先 1〜5 → SDK 11〜15、6〜10 → SDK 6〜10、11〜14 → SDK 1〜4。表示先 11〜14 が実際にどの副画面領域へ現れるかは観測する。

## 判定と記録

| 観点 | 期待する観察 | 失敗・未確認 |
| --- | --- | --- |
| 背景 | BG、格子、赤・緑の目印が画面に現れる | 例外・未表示・異なる表示。API の正常終了だけでは未確認 |
| 通常ボタン | D1〜D10 が各 1 箇所に読める向きで表示される | 欠落、重複、切れ、向き・色の異常。位置は実測して記録 |
| 副画面 | D11〜D14 がそれぞれ別領域に表示される | 欠落、重複、切れ、向き・色の異常 |
| タッチ | 操作した位置に対して座標が記録される | 無反応・明らかな欠落。座標の範囲や向きは実測し、想定と違うだけでは API 違反と断定しない |
| スワイプ | 左右でそれぞれ `Swipe` と方向が記録される | 無反応、逆方向、異なるイベント |
| ボタン入力 | 個々の押下で `input-N` を記録できる | 無反応、別の位置と区別できない。表示先の番号との一致は要求しない |

JSONL の操作名と入力を照合し、画面の写真とともに判定する。`display-N` と `input-N` は独立した番号である。画面の写真は JSONL に自動では含まれない。

## 既存テストと実機確認の境界

PR #24 は fake transport と固定 SDK で描画先変換、画像変換、イベントの受け渡しを検証済み。fake の成功は実機の画像位置、表示形式、座標と画面位置の対応、左右スワイプ、描画完了を保証しない。今回の fixture が出力した送信ログも実機の成功を証明しない。実機で観測・記録するまで各項目は未確認とする。
