# ボタン能力の基本設計

[ボタン入力の要件](../requirements/buttons.md)を具体化する。
上位が理想入力を定め、下位が実現する依存方向は[共通の基本設計](../design.md)に従う。

## 契約と責務

Buttonを、現在の押下状態の照会Read、開始・終了の取得Input、Observerによる通知Subjectを合成した能力とする。
照会、取得、通知は個別の能力として利用できる。ボタンは継承を必須としない抽象契約であり、
機器のクラスを基底にしない。短押し・長押しの認識や操作の選択・実行は含めない。

開始・終了は、変化後の押下状態と取得時点を持つ不変のChangeとして順に取得する。
現在状態の照会は最新の状態を返し、過去のChangeの状態に巻き戻らない。
通知は取得を予約するだけとし、通知数を変化数と対応させない。
各Buttonの取得側は一つとし、複数のObserverが同じ履歴を奪い合わない。

ButtonProductは、一つのLinkと、上位のSlotで識別したButtonの集合を提供する。
集合は構成後に変更せず、関連製品が同じ接続と状態を共有する。
上位はSlotで入力を選び、物理番号やSDKの状態値を解釈しない。

## 単発入力との関係

既存のInput<Slot>とButtonは別の利用契約とする。
既存のFactory契約はmakeで既存の製品、ButtonFactory契約はmake_buttonsでButtonProductを構成する。
具体的なFactoryは両方の能力を提供でき、組み立て側が利用契約を選ぶ。
必要な経路だけを生成し、利用しない経路の履歴を蓄積しない。
既存の単発入力の配送・実行規則は変更しない。

複数入力の継続状態は、単発操作の競合解決とは分ける。
同時押しのButtonは全構成入力が保持された時に開始し、一つでも終了すると終了する。
個別Buttonの状態は抑制しない。同時押しの優先や単独操作の抑制が必要なら、利用側が解釈する。
この経路に短押し・長押しの分類、タイマーや共通閾値は置かない。

## 整合条件

- Linkの開始と初期化が完了するまで入力を受理しない。開始前に保持状態を確認済みとは扱わない。
- 開始時の状態は未押下を初期値とする。接続時点で既に保持された入力の復元は保証しない。
- 同じ状態の重複通知は新しい変化とせず、順序を維持する。
- 状態更新と履歴への追加を順序付け、Observerはすべての内部ロックを解放してから呼ぶ。
- 切断・終了・取得失敗では保持状態と未取得の履歴を無効化する。正常な終了を合成しない。
- 利用不能はInputErrorで知らせる。照会でも未押下と取り違えない。再開時に履歴と失敗を初期化する。
- 履歴を受理できない場合は接続の入力経路全体を失敗させ、他のButtonだけを正常として続行しない。
- 引き渡し済みのChangeは不変の過去記録であり、切断後の現在状態を保証しない。

継続状態の算出は純粋な計算、取得時点の採取・状態保持・配送は副作用とする。
時刻の表現、同期、蓄積とSDKへの具体的適合は[詳細設計](../implementation.md)で扱う。
